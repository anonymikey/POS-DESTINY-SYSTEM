================================================================================
REQUIRED ENVIRONMENT VARIABLES (MUST HAVE THESE)
================================================================================

Variable Name: NEXT_PUBLIC_SUPABASE_URL
Type: Public (Client-side)
Description: Your Supabase project's base URL
Example Value: https://abcdef1234567890.supabase.co
Where To Get It: 
  1. Go to https://supabase.com/dashboard
  2. Select your POS project
  3. Click "Settings" → "API"
  4. Copy the "Project URL"

---

Variable Name: NEXT_PUBLIC_SUPABASE_ANON_KEY
Type: Public (Client-side - Safe to expose)
Description: Your Supabase public/anonymous API key
Example Value: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9[...long string...]
Where To Get It:
  1. Go to https://supabase.com/dashboard
  2. Select your POS project
  3. Click "Settings" → "API"
  4. Copy the "anon public" key (NOT the service_role key)

================================================================================
OPTIONAL ENVIRONMENT VARIABLES
================================================================================

Variable Name: NEXT_PUBLIC_API_URL (Optional)
Type: Public (Client-side)
Description: Your custom API endpoint (if using custom backend)
Example Value: https://api.yourpos.com
Default: Not used (connects directly to Supabase)
When To Use: Only if you have a custom backend API layer

---

Variable Name: NODE_ENV
Type: Private
Description: Node environment (auto-set by Vercel)
Value: production
Note: You don't need to set this - Vercel does it automatically

================================================================================
HOW TO ADD TO VERCEL
================================================================================

METHOD 1: Vercel Dashboard (Recommended)

1. Open https://vercel.com/dashboard
2. Click your "pos-destiny-system" project
3. Click "Settings" (top menu)
4. Click "Environment Variables" (left sidebar)
5. Click "Add New" and enter:
   
   Field: Name
   Value: NEXT_PUBLIC_SUPABASE_URL
   
   Field: Value
   Value: [Your Supabase Project URL]
   
   Field: Environments
   Value: Select "Production" (check all environments if you want)
   
   Click "Save"

6. Repeat step 5 for NEXT_PUBLIC_SUPABASE_ANON_KEY

---

METHOD 2: Vercel CLI

In terminal:

  vercel env add NEXT_PUBLIC_SUPABASE_URL
  # Paste your Supabase URL when prompted
  
  vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY
  # Paste your Supabase anon key when prompted

---

METHOD 3: Local Development (.env.local)

Create file: /vercel/share/v0-project/.env.local

Content:
  NEXT_PUBLIC_SUPABASE_URL=your_supabase_url_here
  NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key_here

Note: Never commit .env.local to Git! Add to .gitignore

================================================================================
COMMON MISTAKES (AVOID THESE)
================================================================================

❌ MISTAKE 1: Using service_role key
   Wrong:  NEXT_PUBLIC_SUPABASE_ANON_KEY = eyJhbGciOiJIUzI1Ni... (service_role)
   Right:  NEXT_PUBLIC_SUPABASE_ANON_KEY = eyJhbGciOiJIUzI1Ni... (anon public)
   
   FIX: Copy "anon public" key, NOT "service_role" key

---

❌ MISTAKE 2: Wrong variable prefix
   Wrong:  SUPABASE_URL (missing NEXT_PUBLIC_)
   Right:  NEXT_PUBLIC_SUPABASE_URL
   
   FIX: Always include "NEXT_PUBLIC_" prefix for client-side variables

---

❌ MISTAKE 3: Extra spaces in values
   Wrong:  " https://xyz.supabase.co " (has spaces)
   Right:  https://xyz.supabase.co (no spaces)
   
   FIX: Copy/paste carefully, check for leading/trailing spaces

---

❌ MISTAKE 4: Forgot to redeploy
   Added variables but page still blank
   
   FIX: Always redeploy after adding/changing environment variables
   Click "Redeploy" in Vercel dashboard OR run: vercel --prod

---

❌ MISTAKE 5: Stored .env.local in Git
   Committed secrets to GitHub
   
   FIX: Add .env.local to .gitignore
   Never commit environment variables

---

❌ MISTAKE 6: Used custom domain URL instead of supabase.co
   Wrong:  https://mypos.customdomain.com
   Right:  https://xyz.supabase.co
   
   FIX: Always use the official Supabase project URL

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: Landing page still shows blank after adding variables

DIAGNOSIS:
1. Check Vercel env vars are set:
   → Go to Vercel Settings → Environment Variables
   → Verify BOTH variables are listed with correct values

2. Hard refresh browser:
   → Windows: Ctrl + Shift + R
   → Mac: Cmd + Shift + R

3. Check browser console for errors:
   → Press F12 to open Developer Tools
   → Click "Console" tab
   → Look for red error messages

4. Test Supabase connection (in browser console):
   → console.log(process.env.NEXT_PUBLIC_SUPABASE_URL)
   → Should display your Supabase URL
   → If undefined, variables not loading

5. Check Vercel deployment:
   → Go to Vercel dashboard
   → Click "Deployments" tab
   → Click latest deployment
   → Check build logs for errors

---

ISSUE: "Cannot connect to Supabase" error in console

CAUSE: Invalid URL or key

FIX:
1. Verify Supabase project is running (not paused)
2. Copy credentials again exactly as shown
3. Check for typos or extra spaces
4. Make sure it's "anon public" key, not "service_role"
5. Redeploy after fixing

---

ISSUE: Admin dashboard shows empty (no data)

CAUSE: Database schema not created or RLS blocking access

FIX:
1. Go to Supabase dashboard
2. Click "SQL Editor"
3. Check if tables exist (products, orders, customers, etc.)
4. If no tables, run DATABASE_SCHEMA.sql file
5. Add test data to verify connection works

================================================================================
SECURITY NOTES
================================================================================

✅ SAFE TO EXPOSE (with NEXT_PUBLIC_ prefix):
   - NEXT_PUBLIC_SUPABASE_URL
   - NEXT_PUBLIC_SUPABASE_ANON_KEY (anon public key only)

✅ PROTECTED BY SUPABASE:
   - Row Level Security (RLS) policies
   - Authentication requirements
   - API rate limiting

❌ NEVER EXPOSE:
   - Service role key (server-side only)
   - JWT secrets
   - Database passwords

BEST PRACTICES:
- Always use NEXT_PUBLIC_ for client-side variables
- Rotate keys periodically
- Monitor Supabase usage in dashboard
- Use RLS policies for production
- Never commit .env.local to Git
